Features

Everything FairwayDB does, one section at a time.

FairwayDB is a desktop client for PostgreSQL, built for people who spend their day in a database. This page walks through each part of the app: what it's for, how to use it, and the details that make it different.

Getting connected

Connections

The first screen lists your saved and recent connections, each with a colour tag you pick, and a filter box. That colour follows you around: it names the workspace in the tab strip and underlines the status bar, so you always know which database you're typing into.

  • Import from URL. Paste a postgres://user@host:5432/db string and every field fills in. Copy URL turns a saved connection back into one.
  • Test before you save. The form checks the connection before it's stored.
  • Several databases at once. Connect to as many as you like. Every tab remembers which connection it belongs to.
  • Sealed passwords. In the desktop app, passwords are encrypted with AES-256-GCM under a key your OS keychain holds.

Safe mode & TLS

Mark a connection read-only and the server refuses every write: edits, inserts, deletes. Raw SQL on that connection runs inside BEGIN TRANSACTION READ ONLY, so Postgres itself turns a stray DELETE away. The buttons aren't just hidden.

BEGIN TRANSACTION READ ONLY;
delete from orders where status = 'cancelled';
ERROR: cannot execute DELETE in a read-only transaction

TLS has three modes. New connections start on the strictest one:

Mode What it does
Verify certificate verify-full Encrypts and checks the server's certificate and host name. Add your own CA when the certificate isn't publicly signed. This is the default.
Encrypted only require Encrypts, but doesn't verify who's on the other end.
Disabled disable Plain TCP, for a local database.

Finding your way

Schema browser

The sidebar lists the tables and views in the current schema with row estimates. Expand a table to see its columns and keys. Inheritance and partition markers mean a child table never passes for a plain one.

  • Filter the list with plain text or a /regex/, such as /^(order|invoice)/.
  • Right-click any table to open it, view its structure or ERD, export it, or copy its name.
  • Dump a whole schema as SQL in one click: DDL plus INSERTs, with parents before children so it replays cleanly.

Pinned tables

Pin the tables you use every day and they stay at the top of the sidebar. Group them into your own named categories and drag to reorder them. Pins belong to the connection rather than the schema, so a pinned table from billing is still there while you browse public, marked with a dim schema prefix.

Command palette

Press ⌘K (or ⌘P) and type. One list covers actions, tables, columns, saved queries, connections and schemas, and it takes /regex/ too.

Tabs, workspaces & windows

Each connection is its own workspace. The tab strip shows only the active connection's tabs, headed by its colour chip. Switch connections and that connection's tabs come back as you left them. The connection picker shows how many tabs each one has open.

  • Tabs survive a reload, reorder by dragging and close on middle-click.
  • ⌘1–9 jump between the tabs of the current workspace.
  • ⇧⌘N opens a new window on the same connection with its own tabs. Pins, layouts and saved filters are shared between windows, and the window layout comes back on the next launch.

Working with rows

The data grid

Opening a table shows its rows in a paged grid. Click a header to sort, drag it to reorder, and drag its edge to resize. Column types show beside each name. The layout and the sort you left are remembered for each table.

  • Column layout is built for the hundred-column table. Filter the columns (with /regex/), multi-select, add or remove in bulk, and reorder by dragging or with ↑ ↓ ⤒ ⤓.
  • Exact counts on demand. The pager shows row ranges. Press Count when you really want count(*) on a large table.
  • Select rows by clicking row numbers. Shift and ⌘ extend the selection, and dragging down the gutter selects a run.

Filter builder

Build a WHERE clause without writing one. Pick a column, an operator and a value, then chain more lines with AND or OR. Operators are phrased as intent: contains adds its own wildcards, so you never type %.

created_atbetween2026-09-01and2026-09-30
emailmatches regex/@acme\.io$/
planis one ofproteamenterprise

The operators and value editors follow the column's type. Booleans and enums get a picker, dates and numbers get typed inputs, and text columns suggest values they actually hold. Values are bound as the column's own type, so > orders numbers and dates correctly and your indexes still apply.

Saved filters. Name a filter set and reload it later from the filter bar. Saved filters belong to the connection and travel with a portable workspace.

Search omnibox

For a quick search, type into the omnibox above the grid. A bare word searches every column. Prefix it with a column name to narrow it. Terms are combined with AND.

You type It finds
hammer Rows where any column contains “hammer”
"two words" Any column containing the whole phrase
name:ham name contains “ham”
qty:>20 qty greater than 20, compared as a number (also <, >=, <=, !=)
status:=active status exactly equals “active”
note:~^a.*z$ note matches the regex

A word: prefix that isn't a real column is treated as plain text, so pasting a URL or a timestamp still works.

Editing rows

Edits don't hit the database as you type. Change a cell, insert or clone a row, set a value to NULL or mark rows for deletion. Each change is highlighted where it happened, and then all of them are written at once with Apply, in one transaction.

id status total
1 10482 delivered 249.00
2 10481 shipped 1120.50
3 10433 cancelled 61.20
+ auto pending 89.00
4 changes staged SQL Apply
  • Review first. Copy the staged changes as SQL to read them, or to run them somewhere else.
  • Bulk delete. Select rows in the row-number gutter and delete them together.
  • Choices, not codes. Enum columns and foreign keys are edited with a picker that searches the referenced table by its label. You can still paste a raw key.

JSON panel

Click a json or jsonb cell and it opens in a side panel as a tree that still reads as JSON, with braces, quoted keys and syntax colour. There's no separate tree mode and text mode to switch between. 

{
  "customer": {
    "id": 4812,
    "tier": "gold",
    "verified": true
  },
  "tags": ["gift", "rush"],
  "note": null
}
  • Fold any object or array from the gutter.
  • Filter keys and values with text or a /regex/.
  • Edit values in place. The change is staged like any other cell edit.
  • Copy the path to any node.

Foreign keys & magic columns

A foreign-key cell carries a jump icon . Click it to open the referenced table filtered to that row. In the JSON panel, foreign keys show as chips that expand to show the row they point to.

Magic columns turn query results into visual cells. Alias a column with a suffix and the grid renders it for you:

Alias ends in Renders as
__format__stars ★★★★★ for 0–5
__format__progress for 0–100
__format__check ✓ / ✗
__format__money · __format__number $1,234.50 · 1,234,567
__format__image · __format__url · __format__email An inline thumbnail, a clickable link, a mailto link
__link__users or __link__users__uid A button that opens users filtered on id (or uid) 
select name, score as score__format__stars, owner_id as owner__link__users
from reviews;

Export

Export what you're looking at, with its filters applied, or the whole table as CSV, JSON or SQL. To dump an entire schema, use the sidebar's schema dump.

Writing SQL

SQL editor

⌘T opens a query tab. The editor autocompletes from your schema, so table and column names come from the database rather than guesswork. Results land in the same grid as a table, with the JSON panel, foreign-key jumps and magic columns all working.

⌘↵ Run
⇧⌘↵ Run the entire buffer
⇧⌘F Format SQL
⌘F Find & replace

On a read-only connection, everything you run goes through a read-only transaction.

History & saved queries

Every query you run is recorded, including failures, with its timing or error. Filter the history with text or /regex/. Click an entry to load it into the editor, or double-click to run it again.

select * from orders where status …6 ms
update orders set total = …read-only
explain analyze select c.name …41 ms

Save the queries you'll need again. They show up in the command palette and travel with a portable workspace.

Understanding a schema

Structure

The structure tab shows everything that defines a table in one place: columns with primary-key and inherited markers, foreign keys, indexes and reconstructed DDL. Extends and Extended by link to parent and child tables through inheritance and partitioning.

ERD

Draw an entire schema as an entity-relationship diagram. Each table is a card, and each edge connects the exact foreign-key column to the primary-key column it references. Pan the canvas, spotlight one table to fade the rest, and hide tables you don't need.

Related rows

Start from one row and see everything linked to it. Its children appear below, and their parents above. Pure join tables collapse into direct links, and composite keys work.

  • Set how many hops to follow and how many rows to fetch per link.
  • Drag and resize the cards.
  • A capped card links out to the full result in a normal table tab.

AI assistant

Open the assistant and ask in plain English. It uses read-only tools to list schemas and tables, describe a table and run a SELECT, so its answers come from your actual schema rather than a guess at column names.

Assistant
How many orders shipped late last month?
describe_table · orders run_sql · 1 row
SQLCopyInsertRun 
select count(*) from orders
where delivered_at > promised_at
  and delivered_at >= date_trunc('month', now()) - interval '1 month';

38 orders arrived after their promised date.

Ask about your schema…
  • Replies stream in, and every tool call it makes is shown.
  • SQL in a reply comes with Copy, Insert into editor and Run.
  • Every query it runs uses a READ ONLY transaction. It can look, but it can't change anything.
  • Bring your own Anthropic API key, or point it at a LiteLLM or other Anthropic-compatible proxy. The key is sealed like a password and never reaches the UI.

Making it yours

Portable workspaces

Set up staging the way you like, then take the setup to production. Export a connection's pins, saved filters, table views and saved queries to one JSON file, and import it onto another database with the same shape.

  • One panel shows what each side holds before anything moves.
  • Choose which sections to include.
  • An import overwrites only what the file names and leaves everything else alone.

Settings & theme

Dark mode is the default and what the app is designed around. Light mode is one click away in the title bar. Settings, reachable from the palette, hold the assistant's API key, model and proxy URL, plus a statement timeout for what you run in the SQL editor.
