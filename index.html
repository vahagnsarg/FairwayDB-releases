Features

Everything you reach for, one keystroke away.

Follow a row wherever it goes

An assistant that sees your schema

Ask in plain English. It looks up the tables it needs, checks its query against your data in a read-only transaction, and hands you SQL you can insert or run in one click.

  • Reads columns, keys and types — never guesses a name
  • Can only read: every query it runs is READ ONLY
  • Bring your own Anthropic key, or point it at your proxy

Who were our top 5 customers by delivered revenue this quarter?
describe_table · orders describe_table · customers run_sql · 5 rows

Join orders to customers on customer_id and keep delivered orders from this quarter:

SQLCopyInsertRun 
select c.name, sum(o.total) as revenue
from orders o
join customers c on c.id = o.customer_id
where o.status = 'delivered'
  and o.delivered_at >= date_trunc('quarter', now())
group by c.name
order by revenue desc
limit 5;

Ada Lovelace leads with $4,812.40 across 11 orders, ahead of Grace Hopper at $3,907.15.

Safe mode means safe

Mark a connection read-only and every write is refused by the server. Raw SQL runs inside a read-only transaction, so it's Postgres that says no.

BEGIN TRANSACTION READ ONLY;
delete from orders where …
ERROR: cannot execute DELETE in a read-only transaction
